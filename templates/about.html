Project Architecture

About ShopFinder

A full-stack smart shopping comparison platform designed to help shoppers search once and compare offers across multiple e-commerce websites.

Python Syllabus Integration

Unit I (Variables, Operators, Conditionals):

Budget level classifications (Low, Medium, High, Premium), percentage discount calculations, and conditional availability flags.

Unit II (Functions & Reusable Types):

Functions with parameters, return types, and default arguments: search_products(), filter_by_budget(), sort_products_by_price(), calculate_discount(), validate_product_data().

Unit III (Dictionaries, Tuples, Sets):

Dictionaries for product payloads, tuples for immutable validation results, and sets for eliminating duplicate brand and category identifiers.

Unit IV (Files & Object-Oriented Programming):

Application logging in app.log, OOP classes (Product, ShoppingPlatform, ProductOffer, PriceTracker).

Unit V (Data Science, JSON, XML, Pandas & DataFrames):

RESTful JSON APIs, XML export, and Pandas DataFrames computing summary price statistics, average discounts, and platform volumes.

Algorithms and Data Structures (ADS)

1. Trie (Prefix Tree) — Autocomplete:

O(L) time complexity where L is the prefix length. Powers instant search bar auto-suggestions.

2. Merge Sort (Divide & Conquer):

Guaranteed O(N log N) sorting by price (ascending/descending), rating, and discounts.

3. Linear Search & Binary Search:

O(N) partial name & category matcher, and O(log N) price boundary finder on pre-sorted arrays.

4. Min-Heap / Priority Queue:

O(K log N) heap extraction to retrieve lowest-cost offers without sorting full arrays.

Data Integration Transparency Notice

ShopFinder currently runs on verified demonstration data stored in SQLite. Live commercial connections to Amazon Product Advertising API (PA-API) or Flipkart Affiliate Feeds require authorized partner credentials, developer API keys, and affiliate agreement approval. The codebase is architected with an extensible Adapter pattern (integrations/base_adapter.py) allowing live API adapters to be activated seamlessly upon credential acquisition.
